# Sailing Yachts — Future Roadmap (Phase 6+)

Created: 2026-04-06
Status: Proposed
Priority order: SEO & traffic growth → monetization → engagement → platform expansion

## Current Baseline From Code Audit

- Public UX already exists for home, yacht browse/filtering, manufacturer pages, yacht detail pages, compare, search, favorites, newsletter signup, reviews, public API docs, and an embeddable compare widget.
- Technical baseline is solid: Next.js 14 App Router, Drizzle ORM, Neon PostgreSQL, Playwright coverage, dynamic sitemap/robots/feed, JSON-LD, and Core Web Vitals tracking.
- Monetization baseline exists through affiliate recommendations and sailboats.fr cross-linking, but there is no real price intelligence, partner lead routing, or premium layer yet.
- Engagement baseline exists only for anonymous users through `localStorage` favorites and saved comparisons; there are no public user accounts, saved searches, or alerts.
- Major near-term opportunity: most public pages are still `force-dynamic` and client-heavy, which limits crawl efficiency, page speed, and long-tail landing page growth.
- Major trust gap to fix before scaling SEO: marketing copy and FAQ text currently claim “1,000+ yachts,” while `ROADMAP.md` and API docs point to roughly 201 models. Future work should treat data truthfulness as a P0 requirement.
- Security/platform debt exists around auth: `next-auth` is present, but admin auth still uses hardcoded credentials and is not a foundation for public accounts.

## Execution Rules For The Cron Agent

Every roadmap item below should be treated as an issue-sized autonomous PR with the same definition of done:

- Add or update tests closest to the change first, then run broader validation.
- Pass `npm run typecheck`, `npm run build`, and the relevant Playwright specs before merge.
- Update docs, metadata, analytics events, and internal links when the user-facing surface changes.
- Ship risky changes behind a feature flag or phased rollout when possible.
- Open one focused PR per item, deploy, verify production behavior, then close the issue with a short summary.

## Phase 6 — SEO Foundation & Programmatic Landing Pages

**Priority:** Highest  
**Primary goal:** Turn the current database into a crawlable search-demand capture engine.  
**Phase success metrics:** +300 to +1,000 new high-quality indexable pages, improved Search Console coverage, lower crawl waste, faster public page loads, higher CTR from long-tail queries.

### What This Phase Should Deliver

- Trustworthy sitewide stats and claims, with live counts and “last updated” dates.
- Crawl-friendly collection pages for high-intent yacht buyer searches.
- Better internal linking between yachts, manufacturers, comparisons, and guides.
- Richer schema coverage for list pages, comparison pages, images, reviews, and offers.
- Faster public pages through ISR/caching instead of everything being rendered dynamically.

### Concrete PR-Sized Backlog

- **P6.1 — Live stats service + truthfulness pass:** Create a `site-stats` helper that reads manufacturer/yacht counts from the database and replace all hardcoded “1,000+” copy on the homepage, FAQ, metadata, and API docs. Tests: Playwright assertions on homepage copy and metadata snapshots.
- **P6.2 — Public page caching strategy:** Remove `force-dynamic` from the homepage, manufacturer pages, yacht detail pages, and SEO landing pages where data freshness can be handled with `revalidate` and `revalidateTag`. Tests: build validation, route rendering checks, and regression tests for cache invalidation after admin edits.
- **P6.3 — Programmatic long-tail landing pages:** Create reusable templates for high-intent pages such as `/best/40-foot-cruising-sailboats`, `/best/bluewater-sailboats-under-45-feet`, `/best/liveaboard-sailboats-with-3-cabins`, and `/best/performance-cruisers-under-35-feet`. Tests: snapshot content assertions, internal link checks, canonical validation.
- **P6.4 — Canonical “X vs Y” pages:** Add friendly comparison routes like `/compare/beneteau-oceanis-34-1-vs-jeanneau-sun-odyssey-349`, backed by the existing compare system. Include canonical tags, unique intro copy, and comparison-specific JSON-LD. Tests: Playwright coverage for canonical URL, heading, and comparison table render.
- **P6.5 — Schema enrichment sweep:** Add `CollectionPage`, `ItemList`, `BreadcrumbList`, `FAQPage`, `ImageObject`, `Review`, and `AggregateOffer`/`Offer` where data exists. Tests: JSON-LD extraction tests and SEO assertions.
- **P6.6 — Split sitemaps + image sitemap:** Break the current sitemap into logical groups (`yachts`, `manufacturers`, `guides`, `compare`, `images`) with better `lastmod` values sourced from DB timestamps. Tests: XML structure validation and route availability tests.
- **P6.7 — Internal linking modules:** Add “compare with similar boats,” “same size alternatives,” “more from this manufacturer,” and “related guides” blocks to yacht and manufacturer pages. Tests: Playwright checks for link presence and no broken-link regressions.
- **P6.8 — Thin-page governance:** Add canonical/noindex rules for low-value filter combinations and deduplicate list pages that only differ by query params. Tests: metadata assertions for indexable vs non-indexable routes.
- **P6.9 — Search intent pages from real usage:** Mine popular search/autocomplete queries and generate curated landing pages for recurring intents like “best family cruiser,” “shoal draft sailboats,” and “sailboats with 3 cabins.” Tests: content generation snapshot tests and SEO metadata coverage.

### Notes

- This phase should create the first real SEO moat.
- The core implementation pattern should be: static shell + cached data + tag-based revalidation + strong internal links.

## Phase 8 — Monetization & Price Intelligence

**Priority:** High  
**Primary goal:** Turn buyer-intent traffic into measurable revenue without degrading trust.  
**Phase success metrics:** affiliate CTR, lead form conversion rate, revenue per 1,000 sessions, premium feature conversion, price-page engagement.

### What This Phase Should Deliver

- Real pricing intelligence instead of vague inferred price tiers alone.
- Better affiliate placement based on page intent and yacht segment.
- Dealer/broker/manufacturer lead capture.
- High-value premium exports or reports for serious buyers.

### Concrete PR-Sized Backlog

- **P8.1 — Price data schema + ingestion:** Add tables for price range, currency, source, source type, confidence score, and historical snapshots. Start with admin import or partner CSV upload. Tests: schema migration tests, API tests, and UI render tests for price blocks.
- **P8.2 — Price insight blocks on yacht pages:** Add “new price range,” “used market range,” “last updated,” and “confidence” UI modules where data exists. Tests: Playwright checks for price rendering and schema assertions for offer markup.
- **P8.3 — Comparison-page monetization:** Add contextual affiliate and partner CTAs on compare pages such as gear recommendations, insurance, charter/demo leads, and broker inquiry forms. Tests: CTA visibility tests and click tracking event assertions.
- **P8.4 — Dealer/broker lead routing:** Build forms like “ask a dealer”, “request market pricing”, and “find a similar used yacht,” routed via email/webhook/admin queue with source attribution. Tests: API validation tests and end-to-end form submission tests.
- **P8.5 — Premium comparison exports:** Offer downloadable PDF/CSV comparison reports, buyer checklists, or shortlist packs for logged-in users. Tests: report generation tests and permission/entitlement checks.
- **P8.6 — Revenue analytics instrumentation:** Track affiliate clicks, compare completion, lead submissions, and price-block engagement by page type and traffic source. Tests: analytics event unit tests and smoke tests around event dispatch.
- **P8.7 — Best-value pages:** Use price + specs + reviews to create indexable pages such as “best value 40ft cruisers” or “cheaper alternatives to [model].” Tests: content generation and metadata coverage.
- **P8.8 — Partner offer pages:** Create manufacturer/dealer landing pages for co-marketing and lead generation with clear disclosures and performance reporting. Tests: route and schema checks.

### Notes

- Every monetization surface should preserve editorial trust.
- Any price or partner data shown publicly should include source/date/confidence metadata.

**Primary goal:** Convert one-time visitors into returning users with persistent value.  
**Phase success metrics:** account creation rate, saved search count, alert open rate, repeat visits, returning compare sessions.

### What This Phase Should Deliver

- Personalized homepage and recommendation flows.

### Concrete PR-Sized Backlog

- **P9.2 — DB-backed favorites + comparisons:** Persist favorites, saved comparisons, and recently viewed yachts to the database for logged-in users while preserving `localStorage` fallback for guests. Tests: migration tests, API tests, and UI sync tests.
- **P9.3 — Saved search builder:** Let users save filter combinations, compare intents, and keyword searches. Tests: form submission, persistence, and search replay tests.
- **P9.4 — Email alert system:** Add scheduled and instant alerts for new matching yachts, new reviews, and price changes. Tests: notification payload tests, unsubscribe tests, and end-to-end subscription flows.
- **P9.5 — Account dashboard:** Add a dashboard for favorites, saved searches, comparisons, alerts, and communication preferences. Tests: dashboard smoke tests and CRUD tests for each saved object type.
- **P9.6 — Personalized recommendations:** Surface “similar to your favorites,” “new since your last visit,” and “compare again” modules. Tests: recommendation logic unit tests and render checks.
- **P9.7 — Web push notifications:** Add optional browser notifications for saved search matches and price changes. Tests: subscription endpoint tests and permission UI coverage.
- **P9.8 — Data portability/privacy controls:** Add export/delete account functionality and clear privacy settings. Tests: account deletion/export tests and admin access controls.

### Notes

- This phase should only begin after the auth/security foundation is strong.
- Use alerts to support both retention and monetization, especially around price and market updates.

## Phase 10 — Data Enrichment & Trust Moat

**Priority:** High  
**Primary goal:** Make the dataset deeper, more accurate, and harder to copy.  
**Phase success metrics:** spec completeness score, number of models with rich media, number of yachts with verified pricing, review count, source coverage.

### What This Phase Should Deliver

- More real yacht models and richer source attribution.
- More photos, diagrams, brochures, video, and 3D/360 assets.
- Better review coverage and stronger trust signals.
- Clear “last verified” and completeness indicators.

### Concrete PR-Sized Backlog

- **P10.1 — Data expansion pipeline:** Extend import tooling to bring the database to a truly marketable scale before claiming “1,000+ yachts.” Add duplicate detection and source normalization. Tests: import validation tests and duplicate-resolution tests.
- **P10.2 — Media asset model:** Add support for brochures, deck plans, interior layouts, videos, 360 tours, and 3D models. Tests: schema tests and render tests for mixed media galleries.
- **P10.3 — Source provenance UI:** Show source URL, source type, last verified date, and completeness score on yacht pages. Tests: metadata/UI assertions and schema checks.
- **P10.4 — Review depth:** Move beyond admin-seeded review snippets to verified user/owner reviews, expert reviews, and rating summaries. Tests: moderation tests, structured data tests, and review submission tests.
- **P10.5 — Spec completeness scoring:** Calculate a visible completeness score per yacht and per manufacturer so thin records can be improved or deprioritized in SEO. Tests: score calculation tests and list-page display tests.
- **P10.6 — Pricing coverage expansion:** Normalize regional prices, used listings, and source-specific price histories. Tests: price normalization tests and UI fallback tests for partial data.
- **P10.7 — User-submitted corrections:** Add correction/report forms for missing specs, bad numbers, and outdated details, routed into moderation/admin review. Tests: API validation and admin moderation flow tests.
- **P10.8 — Rich media schema:** Add `VideoObject`, `ImageObject`, and downloadable brochure metadata to improve search appearance. Tests: JSON-LD validation tests.

### Notes

- Phase 10 is where the brand becomes a data product, not just a browse UI.
- Trust signals should be visible enough that users understand what is verified vs inferred.

## Things To Explicitly Deprioritize Until Later

- **Native iOS/Android apps:** Not needed before the PWA proves retention and push adoption.
- **A full marketplace or classified product:** Wait until there is enough pricing/listing coverage and partner supply.
- **A broad forum homepage:** Keep community anchored to yacht pages first; avoid creating an empty generic community surface.
- **Aggressive monetization overlays:** Trust and SEO come first; avoid popups or heavy lead gates that reduce UX quality.

## Summary

The best Phase 6+ path is not “more features everywhere.” It is:

1. Fix trust + crawlability.
2. Capture long-tail search demand with strong landing pages.
3. Layer in editorial authority.
4. Monetize buyer intent with pricing and leads.
5. Retain users with accounts, alerts, and personalization.
6. Expand the moat with better data, partnerships, i18n, mobile, and community.

If executed in that order, Sailing Yachts can move from a solid niche database to a durable search-driven media + data product.
